## Данные

`documents.jsonl` содержит документы досье.

В досье есть:
- свидетельские сообщения;
- переписка;
- системный журнал;
- правила и исключения;
- противоречащие источники;
- нерелевантные документы.

`claims.jsonl` содержит атомарные утверждения.

Каждый claim хранит один отдельный факт, например:

```text
C15: Экспортный архив был создан в 18:16.
```

Для каждого утверждения указывается документ, точный фрагмент evidence и логический статус.

`questions.jsonl` содержит 12 вопросов разных типов:
- прямые;
- multi-hop;
- временные;
- правило + исключение;
- противоречия;
- недостаточно данных.

Для каждого вопроса есть эталонный статус, ответ и нужные evidence ids.

## Режимы работы

В работе сравниваются три режима.

### A — полный контекст

Модели передаются все документы досье.

### B — BM25 top-15

Сначала BM25 выбирает 15 наиболее релевантных claims, после чего они передаются модели обычным списком.

### C — p-adic context

Используются те же top-15 claims, что и в режиме B, но они группируются по p-adic ветвям.

Путь имеет вид:

```text
[a0, a1, a2]
```

где:
- `a0` — тип источника;
- `a1` — логический статус;
- `a2` — время.

Например:

```text
[0, 0, 1]
```

может означать документальный источник, прямой факт и событие во время инцидента.

## Retrieval

Для поиска используется BM25.

Функция находится в:

```text
src/retrieval.py
```

Она выбирает максимум 15 claims.

Важно, что для режимов B и C используется один и тот же набор claims. Меняется только способ организации контекста.

## p-adic структура

Настройки уровней находятся в:

```text
src/padic_config.py
```

Основная логика находится в:

```text
src/padic.py
```

p-adic расстояние считается по длине общего начала двух путей.

Если пути полностью одинаковые, расстояние равно 0.

Если различаются на первом уровне:

```text
distance = 1
```

Если совпадает только первый уровень:

```text
distance = 1/3
```

Если совпадают первые два уровня:

```text
distance = 1/9
```

для p-adic расстояния не используется.

## LLM

Работа с моделью находится в:

```text
src/llm.py
```

Настройки модели находятся в:

```text
src/llm_config.py
```

Используется:

```text
gpt-oss:120b
```

через Ollama API.

Промпт хранится отдельно:

```text
prompts/system_prompt.txt
```

Модель должна возвращать JSON со следующими полями:

```json
{
  "question_id": "Q01",
  "status": "entailed",
  "answer": "18:16",
  "evidence_ids": ["C15"],
  "counterevidence_ids": [],
  "confidence": 0.99,
  "explanation": "Архив был создан в 18:16."
}
```

Допустимые статусы:

```text
entailed
contradicted
both
insufficient
```

Для проверки структуры ответа используется Pydantic.

## Метрики

В `src/evaluation.py` считаются:

- accuracy логического статуса;
- evidence precision;
- evidence recall;
- evidence F1;
- counterevidence recall;
- точность распознавания `both`;
- точность распознавания `insufficient`;
- доля уверенных неправильных ответов при недостатке информации;
- количество токенов;
- время ответа.

Также оценивается устойчивость модели:
- изменение ответа после перестановки документов;
- реакция на удаление посылки;
- реакция на добавление противоречия;
- стабильность evidence ids;
- разница между flat и p-adic контекстом.

## Стресс-тесты

В приложении есть три стресс-теста.

### Перестановка документов

Документы перемешиваются с фиксированным seed `42`.

Правильный ответ в идеале не должен меняться.

### Удаление посылки

Для multi-hop и временных вопросов удаляется один важный claim.

После этого модель должна перейти в `insufficient` или `both`, если остаётся конфликт.

### Добавление противоречия

В контекст добавляется заранее подготовленное противоречащее утверждение.

Ожидается, что модель сможет заметить конфликт и вернуть `both`.

## Streamlit

Интерфейс находится в:

```text
app.py
```

В нём можно:
- загрузить досье;
- выбрать вопрос;
- выбрать режим A, B или C;
- посмотреть ответ модели;
- посмотреть confidence;
- посмотреть evidence и counterevidence;
- запустить стресс-тест;
- посмотреть p-adic ветви;
- сравнить сохранённые результаты;
- скачать результаты в CSV.

## Установка

Установить зависимости (после создания виртуального окружения):

```bash
pip install -r requirements.txt
```

Пример `requirements.txt`:

```text
ollama
streamlit
rank-bm25
pydantic
pandas
pytest
```

## Запуск Streamlit

Из корня проекта:

```bash
streamlit run app.py
```

После этого приложение откроется в браузере.
